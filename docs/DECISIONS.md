# Журнал решений

> Решение с альтернативами → запись здесь. Чтобы пересмотреть решение, нужна новая причина (замер, отзыв игроков), а не вкус.

Шаблон: `### YYYY-MM-DD — Решение` · Контекст · Выбрали · Отвергли (почему) · Как проверить, что решение верное.

### 2026-11-12 — Замок слева, орда справа
Контекст: замок стоял внизу, атака шла сверху вниз, а экран альбомный и камера ездила влево-вправо в пустоту; HUD снизу закрывал замок и героев.
Выбрали: замок у левого края, враги справа, всё поле на экране, камера стоит. Как Grow Castle, Age of War, Stick War, Plants vs. Zombies.
Почему: ось камеры совпадает с осью атаки; путь орды длиннее (≈1400 vs 810 px) — есть место для постов и время реагировать; спрайты Tiny Swords смотрят влево-вправо и идут «лицом» к замку; низ экрана свободен для панелей.
Отвергли: замок внизу + вертикальный скролл (хорошо только для портрета/мобилки); замок в центре с атакой с двух сторон (сложнее, на одном экране не видно оба фланга — оставлено как идея для усложнения); замок справа (то же, что слева, но против направления чтения).
Проверка: живые игроки не теряют замок из виду, не крутят камеру; бот-баланс ≈ прежний.

### 2026-11-12 — Компенсация длинного пути: MARCH_SPEED = 1.15
Выбрали единый множитель скорости орды вместо правки скоростей каждого врага. С ним бот ≈ 11–12 волн, как до переноса замка (без него ≈ 13).

### 2026-11-12 — ИИ героев: пост + агр по роли + поводок
Выбрали: цели ищутся вокруг поста; ближник — агр 250 и охрана стрелков; стрелки — `range + 70`; поводок; вне поводка — возврат на пост.
Отвергли: «просто увеличить радиус» (герои бегают по всей карте, теряют строй); агр от дальности атаки (танк пассивнее всех).

### 2026-11-12 — Управление героями по модели Kingdom Rush
Выбрали: явный выбор героя → один приказ (земля = точка + марш, враг = фокус) → выбор снимается. Esc/ПКМ — отмена.
Отвергли: «выбранный герой по умолчанию + любой клик двигает его» (случайные приказы); RTS-управление с рамкой выделения (лишний микроконтроль для автобаттлера).

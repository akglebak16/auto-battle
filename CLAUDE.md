# Оплот: Осада — конституция проекта

Этот файл читается в начале **каждого** нового чата. Он главный: если что-то в других документах ему противоречит, прав этот файл (и затем его нужно поправить вместе с другим документом).

## Что это за проект
2D-автобаттлер «Оплот: Осада»: герои защищают замок от волн гоблинов и орков. Между волнами — лагерь (лавка, предметы, рецепты, приказы), между забегами — Цитадель (дерево постоянных улучшений). TypeScript + Canvas 2D + DOM-оверлеи, сборка Vite, десктоп через Electron, веб-версия — однофайловый `play.html` на GitHub Pages.

- Репозиторий: https://github.com/akglebak16/auto-battle (ветка `main`)
- Локально: `D:\games\castle-autobattler` (Windows; `node_modules` собраны под win32)
- Язык общения с владельцем — **русский**. Игра двуязычная: каждая строка для игрока пишется парой `L('рус', 'eng')` (см. `DEV_RULES.md`). Комментарии в коде и сообщения коммитов — английские (как в истории).

## Золотые правила
1. **Сначала понять, потом менять.** Прочитать `STATE.md` + `LESSONS.md`, найти нужное место в коде, запустить игру и посмотреть глазами, если задача про ощущения/интерфейс. Не советовать «в общем» — опираться на код и замеры.
2. **Симуляция не знает про DOM.** `src/game.ts` и `src/data.ts` не трогают `document`/`window`/canvas: они же крутятся headless в `scripts/sim.ts`. Вся случайность — через `this.rnd()` (детерминизм).
3. **Данные — в `data.ts`/`skills.ts`, механика — в `game.ts`, рисование — в `render.ts`, DOM — в `ui.ts`.** Не смешивать.
4. **Баланс меряется, а не угадывается.** Любая правка, влияющая на силу героев/врагов/темп, сопровождается прогоном `npm run sim` до и после (см. `TESTING.md`). Ориентир бота сейчас — в `STATE.md`.
5. **Не ломать сохранения игроков.** Ключи `localStorage` и формат `Meta`/забега менять только с миграцией или новой версией ключа.
6. **Интерфейс не перекрывает поле боя** (зоны экрана — в `DESIGN.md`). Каждое изменение UI проверять на 16:9, ультрашироком (21:9) и узком (4:3/5:4) экране.
7. **Работа сдана, когда:** типы сходятся (`tsc`), игра собрана, проверка в браузере пройдена, баланс замерен (если затронут), документы обновлены (см. ниже), изменения закоммичены, если владелец просил.
8. **Отчёт владельцу** — по-русски, коротко: что изменилось для игрока, что проверено и как, что осталось. Без пересказа шагов.

## Самообучение: протокол обновления памяти
Знания проекта живут в этих файлах, а не в памяти чата. Поэтому **в конце каждой задачи** (до коммита):

1. `docs/STATE.md` — обновить «Текущее состояние», перенести сделанное из бэклога в «Недавно сделано» (держать последние ~10 пунктов, старое удалять — оно есть в git и README), добавить новые идеи/долги в бэклог.
2. `docs/LESSONS.md` — если был баг, неверная гипотеза, потраченное зря время или неочевидная особенность окружения — добавить урок по шаблону. Если урок уже есть — усилить его, а не дублировать.
3. `docs/DECISIONS.md` — если принято решение с альтернативами (раскладка, механика, формула, инструмент) — записать: что выбрали, почему, что отвергли.
4. `docs/ARCHITECTURE.md` / `DEV_RULES.md` / `DESIGN.md` / `TESTING.md` — если изменились структура, константы раскладки, правила, зоны экрана, команды проверки.
5. `README.md` — раздел «Что нового (vX.Y)» для изменений, заметных игроку.
6. Этот файл — только если меняются сами правила игры в разработку (редко). Держать его коротким.

**Старые чаты.** Источник правды — файлы, не прошлые чаты (они могут быть недоступны и содержать опровергнутые гипотезы). Если задача касается того, чего нет в `STATE.md`/`LESSONS.md`/`DECISIONS.md`, а владелец говорит, что это уже обсуждали, — поискать в прошлых чатах, если есть инструмент поиска, и проверить найденное по коду. Всё полезное сразу перенести в docs.

Правила гигиены памяти: писать факты и правила, а не дневник; удалять устаревшее; одна мысль — одно место (ссылка вместо копии); числа (константы, замеры) — с датой.

## Особенности окружения (важно для агентов)
- Сессия Claude может работать в облаке, связанной с компьютером владельца: файлы — через подключённую папку, shell на компьютере — Linux-VM, где **нативные сборщики из `node_modules` (vite/rolldown, typescript 7, electron) не запускаются**. Как собирать в этом случае — `docs/BUILD_RELEASE.md`.
- `git push` из Linux-VM на компьютере владельца не проходит (прокси). Пушить из облачной сессии (GitHub App Claude установлен 2026-11-12) через `git bundle` или попросить владельца выполнить `git push`. Подробнее — `BUILD_RELEASE.md`.
- Перед удалением файлов в папке проекта нужно разрешение владельца; git тоже удаляет свои lock-файлы, поэтому для коммитов разрешение на удаление нужно заранее.
